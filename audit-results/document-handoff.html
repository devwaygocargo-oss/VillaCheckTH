คู่มือ Admin

  1. CMS ใช้เฉพาะ Admin ทุกคนแก้และเผยแพร่ได้: แก้เนื้อหา → บันทึกร่าง → Preview → เผยแพร่ → ตรวจเว็บจริง ประวัติย้อนหลังคืนเป็นร่างก่อนเผยแพร่
  2. แพ็กเกจแก้ราคาและสิทธิ์ในหลังบ้าน กติกาอายุสิทธิ์และข้อความอีเมลแก้ผ่าน CMS มีผลใบใหม่เท่านั้น
  3. ตรวจเอกสารและข้อมูล Villa ก่อนอนุมัติ เมื่อข้อมูลถูกแก้ต้องเข้าตรวจใหม่; ถ้าขอแก้/ปฏิเสธใส่เหตุผล
  4. สลิปให้คนตรวจยอด บัญชี และรายการรับจริงก่อนยืนยันพร้อมเลขธุรกรรม ระบบไม่อนุมัติอัตโนมัติ
  5. ใบเก่าที่ไม่มีบัญชี snapshot ต้องยืนยันบัญชี ณ ตอนสร้างกับทีม ห้ามเดาหรือเปลี่ยนเป็นบัญชีปัจจุบันโดยอัตโนมัติ
  6. หน้าตั้งค่า Admin แสดงความพร้อมบริการ ผล OTP คิวอีเมล ข้อมูลที่ยังขาด ตรวจผลส่งจริงแยกจากการมี credentials; ส่งซ้ำได้หลังแก้ SMTP
  7. Facebook เปิดจาก CMS หลัง Meta อนุมัติและตรวจ Login จริง; OTP ที่ใช้บริการ ready-to-use ให้แก้เทมเพลตใน provider console
  8. รับเรื่องจากฟอร์มแจ้งปัญหาและช่องทางติดต่อ CMS; โน้ตภายในใช้เฉพาะทีมงาน

สำรอง/กู้คืนและดูแลระบบ

ตั้ง BACKUP_SECRET อย่างน้อย 32 ตัวอักษรผ่านระบบเก็บ secrets และ BACKUP_DATABASE_URL/DIRECT_URL แยกจากปลายทางกู้คืน เก็บกุญแจคนละที่กับไฟล์ ไม่เก็บ secrets ใน Git หรือส่งผ่านแชต

npm run db:backup -- /secure/location/villacheck-date.vcb

เป็นสำรองข้อมูลแอป 15 ตารางรวมเอกสาร binary/CMS แบบเข้ารหัสและ snapshot ที่สอดคล้องกัน ไม่ใช่สำรอง SQL schema/roles หรือ PITR ของผู้ให้บริการ ไม่รวม sessions, OTP, OAuth states, rate limits

กู้คืน: สร้างฐานข้อมูลใหม่ที่ว่างและผ่าน migrations แล้ว ตั้ง BACKUP_DATABASE_URL เป็นฐานใหม่ จากนั้น npm run db:restore -- /secure/location/villacheck-date.vcb ระบบปฏิเสธฐานมีข้อมูล ปลายทาง remote ต้อง ALLOW_REMOTE_RESTORE=true หลังผู้ดูแลยืนยันฐานใหม่ แยกบริการส่งข้อความระหว่างซ้อม ตรวจจำนวนรายการ เอกสาร ใบแจ้งชำระ และ QR ก่อนสลับระบบ

ผู้ดูแลต้องกำหนดตารางสำรอง retention พื้นที่เก็บ การตรวจไฟล์ และซ้อมกู้คืนจริงกับผู้ให้บริการ ยังไม่ได้ตั้งตารางหรือสำรอง production โดยอัตโนมัติ

npm run check:health ตรวจ API แบบอ่านอย่างเดียว ออกจากคำสั่งด้วยสถานะผิดพลาดหากบริการผิดปกติ กำหนดผู้รับแจ้งเหตุและตารางรันในระบบขององค์กร; หน้าความพร้อม Admin ใช้ตรวจคิวและสถานะร่วมกัน
